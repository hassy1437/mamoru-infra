## 1. 銘板の文字を写す欄（いまの点検アプリ）

### 1-1. 点検する設備の「製造者名」「型式等」— 13 様式

| 様式 | 写す設備 |
|---|---|
| 第2 屋内消火栓・第3 スプリンクラー・第4 水噴霧・第9 屋外消火栓・第20 連結送水管 | ポンプ・電動機 |
| 第5 泡 | ポンプ・電動機、泡消火薬剤の製造者名、泡合成器の型式、消火薬剤の型式番号（「泡第 ○ 〜 ○ 号」を 2 欄に分けて） |
| 第10 動力消防ポンプ | 本体 |
| 第11の1 自動火災報知 | 受信機 |
| 第11の2 ガス漏れ火災警報 | 受信機・中継器 |
| 第12 漏電火災警報器 | 受信機・変流器 |
| 第14 非常警報 | 操作部・複合装置、増幅器 |
| 第18 排煙 | 排煙機 |
| 第22 無線通信補助 | 漏洩同軸ケーブル・空中線・増幅器 |

- 欄はほぼ「製造者名」と「型式等」の 2 つ（文字の欄 1 つずつ）。**型式と型式番号（検定の番号）を分ける欄は無い**（第5 の消火薬剤の型式番号だけ別の欄）
- 製造年・製造番号の欄は無い
- 確かめ方: 各様式の画面の部品（`src/components/*-bekki*-form.tsx`）を読んだ

### 1-2. 点検に使った測定機器 — 全 23 様式

- どの様式にも表がある（機器名・型式・校正年月日・製造者名）。第11の1 は 7 種、第11の2 は加ガス試験器の名前が紙に刷り込みで、ほかは 6 台まで（`src/lib/bekki-device-table.ts`）
- ★**同じ報告書の中でも、様式ごとに打つ**（ほかの様式へ写す仕組みは無い）。測定機器は業者の持ち物で、どの物件・どの様式でも同じものを使うのに、毎回打つ形
- **業者ごとの機材の台帳は無い**。点検者の台帳（`inspection.inspectors`）はあるが人だけ
- 確かめ方: コードを読んだ（`device-table-inputs.tsx`・`bekki-result-form-base.tsx`）・本番 DB の表の一覧（読むだけ）

### 1-3. 前回の報告書の複製で、銘板の欄はそのまま写る

- 「複製」（DB の関数 `inspection.clone_report_forms`）は様式の中身を丸ごと写す。製造者名・型式等も測定機器の表も写り、業者は様式ごとに「確かめた」を押す
- ＝**2 年目からは確かめるだけ**。撮って読むのが効くのは ①はじめての物件 ②設備を入れ替えたとき ③測定機器（物件をまたいで毎回）
- 確かめ方: 本番 DB の関数の中身を読んだ（読むだけ）

### 1-4. 消火器（第1）

- 様式に製造者名・製造年の欄は**無い**（器種 A〜F と数だけ）。製造年は耐圧性能点検・内部点検の時期を決めるのに要るが、点検票に書く所が無い
- ＝消火器の製造年は「転記」ではなく、物件ごとの消火器の台帳の話（前に出した「消火器の期限」の件）。このメモでは決めてほしいことの 1 つとして残す（8. の Q6）

### 1-5. そのほか

- 端末の文字認識（iPhone のテキスト認識・Google レンズ）でコピーする案内は、1-1 の 13 様式と測定機器の表に出している（2026-10-23）
- 本番の点検アプリのデータは試しの様式 76 件。測定機器が入った様式は 0 件、製造者名・型式等が入った様式は 4 件（2026-10-30・読むだけ）＝使い方の実データはまだ無い
- 読み取りの評価の道具の「機器の種類」は、受信機・中継器・ポンプ・電動機・増幅器・消火器・誘導灯・測定機器・その他 の 9 つ。
  **様式にある変流器・操作部・排煙機・漏洩同軸ケーブル・空中線・動力消防ポンプの本体・泡消火薬剤・泡合成器が無い**（いまは「その他」になる）
  → ★2026-10-30 に足した（Q7。`src/lib/nameplate-reading.ts`）

## 2. 足りないところ

1. 測定機器を、報告書ごと・様式ごとに打ち直している（1 物件で様式が 5 つなら 5 回）
2. 型式と型式番号を 1 つの欄（型式等）に入れる決まりが無い（業者によって書き方がばらつく）
3. 写真から欄へ入れる手段が、端末の文字認識のコピーしか無い（欄ごとにコピーして貼る）
4. 消火器の製造年を持つ所が無い（耐圧性能点検などの時期を出せない）

## 3. 案 A: 測定機器の台帳（業者ごと）— ★おすすめの最初の 1 歩

- 業者が自分の測定機器を**1 回だけ**登録する（機器名・型式・製造者名・校正年月日・製造番号）。登録のときに銘板と校正ラベルを撮って読める（3 社の評価で決めた AI）
- 様式の測定機器の表は「台帳から選ぶ」（チェックを付けるだけ）。その報告書のほかの様式にも同じ機器を入れるかを聞く
- 校正年月日が古い機器は黄色にする（何年で古いとするかは業者が機器ごとに入れる。こちらで決まった年数を置かない）
- **AI が無くても効く**（打つのは登録の 1 回だけ）。読み取りは登録のときだけなので、費用もごく小さい
- 作るもの: 機材の台帳の表（点検者の台帳と同じ形・その業者だけが読み書き）・台帳の画面・様式の「台帳から選ぶ」
- 目安: 3〜4 日

## 4. 案 B: 設備の銘板 → その様式の欄へ

- 1-1 の欄の横に「銘板を撮って読む」。撮る → 読み取り → **確かめる画面**（自信が低い欄と、形の確かめで引っかかった欄は黄色）→「入れる」で欄へ
- 型式等の欄には「型式（型式番号）」の形で入れる（例「P-1A（受第2〜1号）」。Q2）。製造年・製造番号は様式に欄が無いので入れない（読んでも捨てる）
- 読めなかった・断られたときは「読み取れませんでした（手で入れてください）」。入力は止めない
- 作るもの: 読み取りのサーバの口（キーはサーバだけ・回数の上限・使った量の記録）・撮る部品・確かめる画面・13 様式への取り付け
- 目安: 3〜4 日（評価と AI の決定のあと）

## 5. 案 C: 現場でまとめて撮る → あとで様式に振り分け

- 点検の現場で銘板を次々に撮り、あとで AI が「機器の種類」から入れ先の様式と欄の候補を出し、人が確かめて振り分ける
- 撮るのが楽だが、振り分けの間違い（第11の1 の受信機を第11の2 に入れる など）を人が見つける必要がある。作りも大きい（5〜7 日）
- B を使ってみて、欄ごとに撮るのが面倒なら考える

## 6. 写真の扱い

| | 残さない（おすすめ） | 報告書に残す |
|---|---|---|
| 中身 | 読み取りが終わったら捨てる（端末にもサーバにも残さない） | 報告書の写真として残す（後で見返せる） |
| よい所 | 費用・保管・個人の情報の心配が小さい。ポリシーに書くことが少ない | 読み間違いを後で確かめられる |
| 気になる所 | 後で確かめられない（入れる前に人が見比べる前提） | 保存の量と期間を決める必要。ポリシーに書く |

★どちらでも、写真は AI の会社（米国）に送る。ポリシーと画面の同意は設計書 5. のとおり（使う会社が決まってから書く）。
