## 穴は3つありました

### ★穴1 — テンプレートの罫線・図形を見ていなかった（★既に塞いだ）

| | |
|---|---|
| いつ | この件より前 |
| 何を見ていなかったか | ★**テンプレート側の罫線・図形**。テキストとの交差しか数えていなかった |
| なぜ見えなかったか | ★重なりを「テンプレートの**テキストスパン**との交差」の中だけで数えていた。★列挙する方式なので、★列挙し忘れた種類（罫線・図形・網掛け）が丸ごと穴になった |
| 実測 | ★値を縦罫線に跨がせてインクが22画素重なっても★検出0件だった |
| どう塞いだか | ★列挙をやめ、★**インクのマスクそのもの**を見る形にした（`両方のインク = アプリのインク ∧ 刷り込みのインク`）。罫線でも図形でも網掛けでも同じ1本で捕まる |
| 自己診断 | ★「罫線の真上に描いたら検出する」を陽性対照として入れた |

★**記録がコードのコメントにしか無かった**ため、この文書に写しました。

### ★穴2 — アプリが描く「図形」を数える枠が無かった（★今回塞いだ）

| | |
|---|---|
| 何を見ていなかったか | ★**アプリ側の図形**。○は文字ではなく★ベジエ曲線（`drawEllipse`）で描かれる |
| なぜ見えなかったか | ★重なった画素を「★アプリの**テキストスパン**の矩形の中」でしか数えていなかった。★○はテキストスパンを持たないので、★数える枠がどこにも無く、★原理的に必ず0件になる |
| ★見つけ方 | ★重なりをページ全体で数え直し、★スパンの内と外に分けた。★外が **3089px / 17様式** あった＝★全部が「見ていない画素」だった |
| どう塞いだか | ★アプリ層の図形の外接矩形も★**数える枠**に加えた |
| ★誤検出は増えないか | ★増えない。★正しく囲めている○は重なりが**0**。実測でも★448個の○のうち★重なったのは**44箇所**だけ |

★**もう1つの穴が同じ場所にありました** ―― `check-choice-clearance` は
★**横しか測っていませんでした**（`cx±rx` が語を包含するか／左右の隣の語に触れないか）。
＝ ★**縦（`cy`・`ry`）を1度も見ておらず、罫線も見ていませんでした。**

★どう塞いだか: ★定数ごとに○を白紙に描き、★テンプレートのインクと重ねる形にした。
★`check-printed-overlap` と**同じ基準**にしてあります。

★**なぜ静的な検査も要るか**: ★1つのセルに丸は1つしか付かないので、
★生成PDFでは選択肢の一部しか踏めません。★踏めない定数こそ黙って壊れます。
＝ ★実測で、生成PDFで踏めるのは **44箇所**／静的な検算では **59定数のうち45個**。

### ★穴3 — 「記号だけのスパン」を判定から外していた（★今回やめた）

| | |
|---|---|
| 何を外していたか | ★`○ ◯ 〇 △ □ ▽ ◎ ×` だけのテキストスパン（実測 **2793件**） |
| 当時の理由 | 「選択肢を○で囲むのは正しい描き方で、刷り込みと重なって当然」 |
| ★なぜ誤りだったか | ★その○は★**文字ではなく図形**で、この除外に★1つも掛かっていなかった。★実際に外していたのは★**別物** ―― 点検結果の欄に描く `○ / ×` の判定記号で、★あれが刷り込みに重なるのは**正しくありません** |
| どうしたか | ★除外をやめた |
| ★増えたか | ★**増えない**（実測: 判定記号の重なりは0件）。★いま0件でも、原理的に見ていない状態を残さない |

| | |

## ★原因は2つに分かれました（幾何を実測）

★定数ごとに「○の上下」と「字の上下」を突き合わせました。

| 原因 | 件数 | 中身 |
|---|---|---|
| ★**○が大きすぎる**（`ry` が過大） | **43** | ★○の上下が、字の上下より★**2.0pt ずつ外**まで伸びている。★その先に次の行の刷り込みや罫線がある |
| ★**○の位置がずれている**（`cy` が過小・過大） | **2** | ★字の中心と○の中心が合っておらず、★上側が字を切っている（例: `standpipe-bekki20` p2「専用」＝ ○上 215.0 に対し 字上 214.8） |

★**＝ ほとんどは「位置をずらす」ではなく「大きさを変える」です。**

★`ry` は **7.28** と **7.00** の2種類しかなく、★どちらも同じ「2pt 余っている」形でした。
＝ ★様式ごとに違う対処が要るわけではありません。

## ★直し方の案（★まだ直していません）

### ★採らない案: 一律に係数を掛ける（`ry * 0.85` など）

★**採りません。** この repo で★同じ形の失敗を4回しています
（`*0.90` / `*0.85` / `*0.98` / `headerShiftY=-10` ―― ★4例とも症状を隠していただけでした）。
★係数は「なぜその値か」を説明できず、★次にテンプレートが変わると再び合わなくなります。

### ★推す案: テンプレートの実測から `ry` を計算し直す

```
ry ＝ （その語の字の高さ ÷ 2） ＋ 余白
余白 ＝ 上下の「当たってはいけないもの」までの距離から決める（★当たらない範囲で最大）
```

- ★**上流（テンプレートの実測）から決める**ので、値の根拠が説明できます
- ★`cy` も同時に「字の上下の中心」に合わせ直せます（★2件の位置ずれもこれで直ります）
- ★この repo には★同じ形の前例があります（`compute-row-cell-overrides.py` など、
  ★テンプレートを実測して定数を計算するスクリプト）。★新しい形を作りません

★**手順の案**

1. ★計算するスクリプトを書く（★定数を書き換えず、★まず「提案値」を出すだけ）
2. ★提案値で重なりが0になることを、★書き換える前に検算する
3. ★書き換える（★一括置換はしない。★定数ごとに、値と根拠を対で）
4. ★`check-printed-overlap` が **44 → 0**、`check-choice-clearance` が **45 → 0** になることを確認
5. ★ベースラインの差分を**全件**目で見る（★意図した変化だけであること）
6. ★確認できてから `--regen`

### ★どこまで直すか

★**全部（44箇所）直せます。** 段階を分ける理由がありません。

- ★原因が★1つ（`ry` が2pt 過大）にほぼ集約されるので、★101px以上だけ直しても
  ★同じ計算で残り32箇所も直ります。★分けるほうがかえって手間です
- ★1〜5px の14箇所は「かすっている」程度ですが、★同じ原因です。
  ★残すと「なぜここだけ残したか」を後で説明できません
