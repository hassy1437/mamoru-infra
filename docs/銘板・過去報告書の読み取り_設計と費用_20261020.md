## 1. 何を読むか（2 つ）

| | 銘板（めいばん）の写真 | 過去の報告書 |
|---|---|---|
| いつ | 現場で、その場で 1 枚ずつ | 物件をはじめて登録するとき（1 物件 1 回） |
| 入れ先 | 別記の「製造者名・型式等」（受信機・中継器・ポンプ・電動機・増幅器 など 13 様式）、測定機器の欄（名称・型式・製造者名・校正年月日） | 物件・総括表の建物の情報（名称・所在・用途・階数・延べ面積）、ある設備の種類、別記の製造者名・型式等、測定機器 |
| 1 回の量 | 写真 1 枚 | PDF・写真で 10〜40 ページ |
| 急ぐか | 急ぐ（数秒〜十数秒で返したい） | 急がない（あとで届けばよい） |

★2026-10-30: 様式への転記（どの様式のどの欄か・測定機器の台帳・写真の扱い）は `docs/銘板の転記_全様式_現状と設計案_20261030.md`。

### ★読まないもの（決まりにする）
- **過去の判定（良・不良）・不良内容は写さない。** 去年の「良」が入った点検票は、点検していないのに良と出る（消防署への虚偽の報告になりうる）。判定はいまの「初期値『良』＋確かめましたの帯」のやり方のまま
- **過去の点検者（氏名・免状番号・所属会社）は写さない。** 前の業者の人の情報で、自社の点検者は点検者のマスタから入る（録音 102 の 3 のとおり）
- 防火管理者・所有者の氏名は、まず読まない（必要になってから決める）

## 2. 流れ（どちらも「候補を出す → 人が確かめて入れる」）

```
スマホで撮る / PDF を選ぶ
  → 端末で縮める（長い辺 1568〜2048px・JPEG）。★撮影場所（位置情報）などの付帯情報もここで落ちる
  → アプリのサーバー（Route Handler）へ送る。★ログインと「自分の物件か」をここで確かめる
  → サーバーから Anthropic の API へ（API キーはサーバーだけ。画面のプログラムには入れない）
  → 決まった形（JSON）で返す：欄ごとの値・読めたかどうか・自信の度合い
  → 画面に「読み取り結果」を出す：写真と並べて、欄ごとに「入れる／入れない」
  → 「入れる」を押した欄だけ入れる（あとは今までの自動保存）
```

### ★決まり
1. **入っている値を黙って上書きしない。** 空の欄だけ「入れる」に印を付けておき、入っている欄は「いまの値 → 読んだ値」を並べて、人が選ぶ
2. **読めない字は空で返させる（推測させない）。** 指示で「見えない字を補わない・読めないときは null」と決め、返す形（JSON の型）でも null を許す
3. **自信の低い欄は黄色で出す**（「確かめてください」）
4. **写真はサーバーに残さない**（受け取って AI に渡したら捨てる）。いまの写真は端末の中だけ（IndexedDB）で、プライバシーポリシーの「5. ローカルデータ」もそう書いている
5. 使った量（誰が・何トークン・いくら）は記録する（月の上限と、業者ごとの回数の上限に使う）

### 返す形（例：銘板）
- 機器の種類（受信機／中継器／ポンプ／電動機／増幅器／消火器／誘導灯／測定機器／その他）
- 製造者名
- 型式（例「P-1A」）・型式番号（例「受第 2〜1 号」）
- 製造年（銘板の書き方のまま＋西暦にしたもの）・製造番号
- ★消火器の「加圧式・蓄圧式」（2026-10-30 に足した・内部と機能の点検の時期が変わる。`docs/消火器の台帳_現状と設計案_20261030.md` Q5）
- それぞれに「読めた／一部／読めない」と自信の度合い

AI の「決まった形で返す」機能（structured outputs・`output_config.format` に JSON の型を渡す）を使うので、形の崩れた答えは返ってこない。

## 3. どの AI（モデル）にするか

| モデル | 入力（100 万トークンあたり） | 出力（同） | ひとこと |
|---|---|---|---|
| Claude Opus 5.5 | 4 ドル | 20 ドル | いちばん賢い。考える処理を切れない（`effort` を `low` にして量を減らす） |
| Claude Sonnet 5.5 | 2 ドル | 10 ドル | Opus の半額 |
| Claude Haiku 5.5 | 0.10 ドル | 0.50 ドル | とても安い。ただし 1 回の入力が 10 万トークンを超えると 0.50／2.50 ドル。断られたときの自動の切り替え（fallback）が無い |

- まとめて頼む方式（Batch API）は**半額**。急がない過去の報告書に向く（結果は数分〜長くて 1 日以内）
- 写真は「縦 × 横 ÷ 750」トークンくらい。Opus 5.5・Sonnet 5.5 は長い辺 2576px まで細かく見られ、1 枚の上限は約 4,800 トークン。Haiku 5.5 の上限は作る前に確かめる

★2026-10-30: Anthropic に固執せず、Google（Gemini）・OpenAI（GPT）も同じ写真・同じ指示・同じ採点で比べることにした（評価の道具は 6-2）。
下の値は**未確認**（公式の料金の頁をこの環境から開けず、検索の要約・第三者のまとめから入れた。使う前に公式で確かめる）。

| モデル（評価の道具の名前） | モデル名（既定） | 入力 | 出力 | ひとこと |
|---|---|---|---|---|
| Gemini Flash-Lite（`gemini-flash-lite`） | `gemini-3.1-flash-lite` | 0.25 ドル ★ | 1.50 ドル ★ | Google の安いもの |
| Gemini Flash（`gemini-flash`） | `gemini-3.6-flash` | 0.75 ドル ★ | 3.75 ドル ★ | 「2026-12-31 までの値」とするまとめがある |
| GPT nano（`gpt-nano`） | `gpt-5.4-nano` | 0.20 ドル ★ | 1.25 ドル ★ | OpenAI のいちばん安いもの（OpenAI の発表の要約） |

## 5. 規約・プライバシー（★弁護士の確認点に足したい）

- 写真・PDF を Anthropic（米国）の API に送ることになる。いまのプライバシーポリシーには外部の AI に送ることが書いていない（「4. データの保管」は Supabase だけ、「5. ローカルデータ」は写真をサーバーに送らないと読める）
- **銘板の写真**はふつう個人の情報を含まない。それでも「送ること」は書く
- **過去の報告書**には防火管理者・点検者の氏名、免状番号、所有者名などが載る。外国にある第三者への提供（個人情報保護法 第 28 条）にあたるか、委託として書けばよいかを弁護士に確かめたい。答えが出るまでは、報告書の取り込みは作らない（または人の名前のあるページを送らない作りにする）
- Anthropic の API に送ったものの扱い（学習に使うか・何日残るか）は、作る前に Anthropic の商用の規約で確かめて、ポリシーに書く
- 画面にも、はじめて使うときに「写真を AI（Anthropic）に送って読み取ります」と出して同意を取る
- ★2026-10-30: Google・OpenAI のモデルを使うなら、送り先が増える（どれも米国の会社）。本番で使う会社が決まったら、ポリシーの案の送り先とデータの扱い（学習に使うか・何日残るか）をその会社の分に書き直す。
  **評価で写真を送るときも同じ**なので、評価には銘板の写真だけを使う（人の名前・顔・書類を写さない）。
  Google の API は、無料枠のキーだと送ったものが Google の改善に使われることがある（と各所に書かれている。★公式の規約で確かめる）＝評価にも本番にも、請求先を付けた有料のキーを使う。
  OpenAI は評価の道具で `store: false`（答えを OpenAI 側に残さない設定）にした
- ★2026-10-21: 弁護士に確かめること（6 つ）・プライバシーポリシーの案（第3編 第2条2項・第3条・第7条3項・第8条）・画面の説明の案を、mamoruinfra-web の `docs/規約_確定事項_20260808.md` の末尾「銘板・過去の報告書の読み取り（OCR）」に書いた。Anthropic の API のデータの扱いもそこに確かめた結果を書いた（学習に使わない・標準では保存しない・Batch は 29 日・安全上の判定で最長 2 年）

## 6. 確かめ方（作る前の評価）

1. 実物を集める：銘板の写真 30〜50 枚（受信機・中継器・ポンプ・電動機・増幅器・消火器・誘導灯・測定機器。2026-10-30 から変流器・操作部・排煙機・漏洩同軸ケーブル・空中線・動力消防ポンプ・泡消火薬剤・泡合成器も選べる。斜め・反射・暗い・刻印 を混ぜる）、過去の報告書 5〜10 件（名前は黒塗りで可）
2. 正解を人が書く（欄ごと）
3. 3 モデルで流して、**欄ごとの正答率**・「読めないのに値を作った」件数・実際のトークン数（返ってくる usage）・時間 を表にする
4. 本番に出す条件の案：型式番号・製造者名で「読めないのに値を作った」が 0 件。正答率は 9 割以上（読めないときに空で返すのは可）
5. お金の見込みは、送る前に数える API（count_tokens）で実物の写真・PDF を数えて置き換える

### 6-1. 評価の道具（2026-10-23 に作った・銘板だけ）

- 指示と返す形: `src/lib/nameplate-reading.ts`（★本番の読み取りも同じものを使う。評価と本番で指示を変えない）
  - 欄ごとに「値・読めたか（読めた／あるが読めない／銘板に無い）・自信（高い／低い）」を返させる
  - 考える量（effort）は既定 low。Opus 5.5 は考える処理を切れないので、量だけを決める
- 実行: `scripts/nameplate-eval/run.mts`（`npm run eval:nameplate -- <コマンド>`）。使い方は冒頭に書いた
  1. 写真を `tmp/nameplate-eval/photos/` に入れる（tmp/ は git に入らない）
  2. `init` … 正解の表（CSV・Excel で開ける）の雛形を作る → 人が正解を書く（読めない・無い欄は空）
  3. `check` … 写真と表を確かめ、呼び出しの回数と費用の見込みを出す（API は呼ばない）
  4. `count` … 送る前に数える API で入力トークンを数える（費用はかからない）
  5. `run --yes` … 3 モデルで実行。`tmp/nameplate-eval/out/<日時>/` に summary.md・diff.csv・results.jsonl
- 正誤の決め方: 全角／半角・空白・ハイフンと波ダッシュの仲間の違いは「正解」、株式会社などの書き方だけの違いは「表記ゆれ」、
  正解が空なのに値を返したら「作った」、正解があるのに空なら「空で返した」（安全側）
- 合格の目安（上の 4.）は summary.md に「満たす／満たさない」で出る。「自信ありの誤り」（自信が高いと答えたのに誤り・作った欄）も出す
  （画面で黄色にならずに素通りする欄なので、本番の画面の作りを決める材料にする）
- 自己診断: `node --experimental-strip-types scripts/check-nameplate-eval.mjs`（push 前の検査にも入れた）
- ★まだ測っていない。要るのは API キー（環境変数 `ANTHROPIC_API_KEY`）と、銘板の写真 30〜50 枚と正解

### 6-2. 3 社で比べる・段階方式（2026-10-30 に足した）

- 比べるモデル（既定）: Haiku 5.5・Sonnet 5.5（比べ役）・Gemini Flash-Lite・Gemini Flash・GPT nano・GPT mini。Opus 5.5 は `--models` で足せる
- 3 社とも**同じ指示・同じ写真・同じ返す形・同じ採点**（`scripts/nameplate-eval/providers.mts`）。考える量は同じ言葉（low など）で渡す
  - 決まった形で返させる: Anthropic は `output_config.format`、OpenAI は `text.format` の json_schema（strict）、Google は `responseSchema`
    （Google の形は書き方が少し違うので、同じ形から自動で直す。直せない書き方があれば止める）
  - ★OpenAI・Google は SDK を足さず HTTP で直に呼ぶ（点検アプリの依存を評価のためだけに増やさない）。Anthropic は公式の SDK のまま
  - ★2026-10-30 は OpenAI・Google の公式の資料をこの環境から開けず、呼び方は知っている形で書いた。偽の返事での検査は通したが、本物では一度も流していない。
    初回は `--limit 3` くらいで流し、エラーが出たら results.jsonl の error（API が返した文）を見せてほしい
- キー: 環境変数 `ANTHROPIC_API_KEY`・`OPENAI_API_KEY`・`GEMINI_API_KEY`（または `GOOGLE_API_KEY`）。**キーの無い会社は飛ばす**（あるものだけで比べられる）
- 増えたコマンド:
  - `models` … 使うモデル名が各社にあるかを確かめる（一覧を読むだけ・費用はかからない）。無ければ似た名前を出す → `--id gemini-flash=名前` で替える
  - `report <結果のフォルダ>` … 正解の表を直したあと・段階方式の組を替えたいときに、API を呼ばずに表を作り直す
- 単価: Anthropic 以外は★未確認（表の費用に ★ が付く）。公式で確かめた値は `--price gpt-nano=0.20/1.25` のように渡すと ★ が消える
- **形の確かめ**（`checkNameplateReading`・本番の確かめる画面でも使う予定）: ありえない形だけを拾う（正しいかは分からない）
  - 製造年が 1950 年より前・今年より後、校正年月日が 2000 年より前・今年より後、年の形が無い（和暦は西暦に直して見る）
  - 型式番号が「〇第…号」の形でない、消火器・受信機・中継器・泡消火薬剤で頭の字（消・受・中・泡）が違う
  - 「読めた」と答えたのに値が無い／値があるのに「読めない」「無い」と答えた
  - 加圧式・蓄圧式: 消火器でないのに値がある／「蓄圧式」「加圧式」「化学泡」の語が無い（★2026-10-30 に足した。正解の表の最後の列）
  - 製造者名の一覧（`tmp/nameplate-eval/makers.txt`・1 行 1 社）を置いたときだけ、一覧に無い製造者名
- **段階方式**: 安いモデルで読み、形の確かめで引っかかった写真（＋条件によっては自信が低い欄がある写真）だけ強いモデルで読み直す。
  ★全部のモデルで流した結果から組み立てるので、追加の費用はかからない。summary.md に「読み直した割合・正答率・1 枚の費用（2 回分を足す）」が出る
  - 組は `--cascade haiku>sonnet,gpt-nano>gpt-mini` で決められる。決めないときは、各モデル → それより高く正答率がいちばん高いモデル
  - 「形の確かめで、誤りのある写真をどれだけ拾えるか」も表に出る。拾えない誤りが多いなら、段階方式でも安いモデルは危ない
- ★組と条件は同じ写真で選ぶので、よく見えやすい。本番に使う前に、別の写真 10〜20 枚でもう一度流して確かめる
- ★まだやっていないこと: 文字認識（OCR）の結果を安いモデルに渡す方式（別の API とキーが要る。比べて足りなければ考える）

### 作るときの注意
- API キー（`ANTHROPIC_API_KEY`）はサーバーの環境変数だけ（Vercel）。`NEXT_PUBLIC_` を付けない
- Anthropic の管理画面で**月の使用上限**を決める（使いすぎ・不正利用の止め）
- 長い PDF は時間がかかる（数十秒〜）。画面を待たせず「受け付けました → できたら知らせる」にする
- 断られた答え（`stop_reason: "refusal"`）・読めなかった答えは「読み取れませんでした（手で入れてください）」と出し、入力を止めない
- 指示と返す形は様式ごとに 1 か所にまとめ、検査（scripts/）で「判定・点検者の欄を読ませていない」ことを確かめる

## 8. 決めてほしいこと

1. **どちらから作るか**：銘板が先（すぐ役に立つ・規約の心配が小さい）か、過去の報告書が先か
2. **費用をだれが持つか**：運営が持つ／業者の月額に入れる／1 か月の回数に上限（例 1 社 300 枚）
3. **モデル**：まず Opus 5.5（精度優先・月 1 万円弱の見込み）で始めて、評価で安いものに替える、でよいか
   → ★2026-10-30: 橋本さん「安く高精度に。Anthropic に固執しなくてよい」。評価で 3 社（6-2）を比べてから決める
4. **規約**：弁護士の確認点に「写真・報告書を外部の AI に送ること」を足すか
5. **評価の材料**：銘板の写真と過去の報告書（黒塗り可）を集められるか
