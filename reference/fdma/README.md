# 消防庁 別記様式（正典）

消防用設備等点検結果報告書の別記様式を、消防庁（総務省消防庁）の公開ファイルから取得したもの。

## なぜリポジトリに置くか

Phase 0 以降は「手元のテンプレート（`public/PDF/`）が正典と一致しているか」を問う作業になる。
**比較の基準そのものが固定されていないと、後から「どの版と照らしたのか」が分からなくなる。**
＝ 対照群を固定するためのファイル。

置き場所の判断:
- `.tmp/` に置かない … gitignore 対象で消える
- `public/` に置かない … Web に配信されてしまう

## ★取得時に分かった実態

**bekki5 と bekki10 は、拡張子が `.doc` だが中身は `.docx`（ZIP）** で配信されている。
消防庁側の実態であって壊れているわけではない。拡張子で形式を決めつけると
この2件を「壊れている」と誤判定するので、検査は**マジックバイト**で見ている
（OLE2 `D0CF11E0` と ZIP `504B0304` の両方を受理）。

検査は「0バイトでないか」「HTML のエラーページを掴んでいないか」「マジックバイトが正しいか」
「23件そろっているか」を見る。**落ちたことに気づかず空ファイルや古いものを正典として
扱い続けるのを防ぐため**（同種の事故を過去に踏んでいる）。

## 表構造の読み方

Phase 2（欄の型辞書）は Word の表構造に依存するので、**セル・結合・日本語テキストが
実際に取れること**を確認済み。

```bash
python scripts/extract-fdma-tables.py
```

実測（23/23 で抽出成功。セル数 112〜1206・結合セル 95〜364）:

| 手段 | 可否 |
|---|---|
| python-docx | ✗ `.docx` 専用。本物の `.doc`（OLE2）は読めない |
| antiword | ✗ 表の罫線は読めるが**日本語が全て `?`**（cp932 のマッピングが同梱されていない） |
| **LibreOffice headless（Docker）→ zipfile** | **✓ 採用** |

注意点:
- ローカルに LibreOffice が無いので Docker（`linuxserver/libreoffice`）で `.doc → .docx` 変換する
- **Git Bash は `-v` のパスを Windows パスへ勝手に変換する**ので `MSYS_NO_PATHCONV=1` が要る
- **ZIP を自前で解析しないこと**。Word の出力はローカルヘッダの `size` が 0 で
  セントラルディレクトリ側にしか入っておらず、自前実装では全件「表を読めない」という
  誤った結果になった（変換は成功していたので、原因は正典ではなく読み取り側だった）

変換結果は `tmp/fdma-docx/`（gitignore 配下）。正典そのものではないのでコミットしない。
