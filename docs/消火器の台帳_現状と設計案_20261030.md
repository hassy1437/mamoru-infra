## 1. 何のための台帳か

消火器は 1 本ずつ製造年が違い、製造年から次のことが決まる。点検票の書き方は変わらないが、**どの消火器に何をするか**が変わる。

| 何 | いつ（★下の 2. で確かめること） | 台帳が無いと |
|---|---|---|
| 耐圧性能点検（水圧の試験） | 製造年から 10 年を過ぎたもの。その後は 3 年ごと | 業者が毎回、現地で製造年を見て数える |
| 内部・機能の点検 | 加圧式は製造年から 3 年、蓄圧式は 5 年を過ぎたもの（抜き取りで行える） | 同上 |
| 交換の目安（設計標準使用期限） | 業務用はおおむね 10 年（★法令ではなくメーカーの目安） | 依頼者が知らないまま古い消火器を使い続ける |

## 2. ★決まりの確かめ（作る前に橋本さんに見てほしい）

上の年数は、前に調べた結果（消防庁の点検基準の要約・2026-10-30 の会話）を書いた。作る前に、点検基準の本文で次を確かめる。

- 耐圧性能点検の「10 年」と「その後 3 年」の数え方（製造年の年末から数えるか、製造年月から数えるか）
- 二酸化炭素・ハロゲン化物の消火器（高圧ガスの容器）は、耐圧性能点検の扱いが違うはず（★要確認）
- 内部・機能の点検の抜き取りの割合（台帳は「対象になる消火器」を出すだけにして、抜き取りは業者が決める案）
- 設計標準使用期限は法令ではない。依頼者への言い方は「交換の目安」にとどめ、「使えなくなる」とは書かない

## 3. いまの状態（as-is）

### 3-1. 点検アプリ（app.mamoruinfra.com）

- 第1 消火器の点検票（`src/components/shokaki-bekki1-form.tsx`）が持つのは次だけ。**1 本ずつの情報は持たない**。

- 確かめ方: コードとマイグレーションを読んだ（mamoru-infra の master・mamoruinfra-web の `20260718032002_int3a_match_to_inspection_property.sql`）

### 3-2. マッチングサイト（mamoruinfra.com）

- 依頼・物件では、消火器は「設備の種類」の 1 つ（`lib/fire-equipment.ts`）。本数・製造年は持たない

- **加圧式か蓄圧式か**は読む欄に無い（内部・機能の点検の時期に要る）

## 4. 案

### 案 A: 点検アプリの物件ごとに台帳（業者が入れる）★おすすめの最初の段

- 点検アプリの物件に「消火器の台帳」を足す。1 行 ＝ **同じ型式・同じ製造年・同じ方式（加圧式／蓄圧式）の組**と、その本数・設置場所のメモ
  - 1 本ずつにすると、大きな建物（数十本）で入れるのが重い。製造年が同じなら、することも同じ
  - 設置場所ごとに分けたい業者は、行を分ければよい
- 列: 器種（A〜F）・方式（加圧式／蓄圧式）・製造者名・型式・型式番号・製造年・本数・設置場所のメモ
- 画面で、この点検で**耐圧性能点検・内部点検の対象になる行**と、**交換の目安を過ぎた行**に印を付ける
- 物件に持つので、年をまたいで残る（報告書の複製とは別。消火器を入れ替えたら業者が直す）
- 作るもの: 表 1 つ（業者本人だけ・物件ごと）・台帳の画面・年数の計算と単体テスト。目安 3〜4 日

### 案 B: 台帳から第1 の点検票へ候補を入れる

- 器種ごとの「設置数」を台帳の本数から入れる
- 「消火器の耐圧性能」「内部・機能」の行に、対象の器種（A〜F）の印を付ける
- ★入れるのは候補だけ。人が確かめてから保存する（測定機器の「台帳から選ぶ」と同じ形）
- 目安 2 日（案 A のあと）

### 案 C: 依頼者に見せる・知らせる（マッチングサイト）

- 依頼者の物件の画面に「消火器の交換の目安」（例: 「5 本が交換の目安を過ぎています」）
- 毎朝の知らせ（`notify-due-reminders`）に、交換の目安を足す
- ★交換の見積もりの依頼につながる。業者にとっても仕事になる
- ★データは業者の台帳にある。依頼者に見せるには、成約でつながる物件だけ、件数と年数を返す口を DB に作る（業者の台帳をそのまま見せない）
- 目安 3〜4 日（案 A のあと）

### 台帳を誰の物にするか（大事な分かれ目）

| | 業者の物（点検アプリの物件・案 A） | 依頼者の物（マッチングサイトの物件） |
|---|---|---|
| 入れる人 | 成約した業者 | 成約中の業者（依頼者も見られる） |
| 業者が替わったら | 前の業者の台帳に残る。新しい業者は入れ直し | 依頼者の物件に残る。新しい業者が引き継げる |
| 作りやすさ | ★点検アプリの今の形（物件は業者ごと）のまま | 成約中の業者だけに書かせる守りが要る（RLS・関数）。大きい |
| 向く時 | まず業者の手間を減らす | 業者が替わっても続くことを売りにする |

### 9-2. ★橋本さんに条文で確かめてほしいこと（DB を当てる前に）

決まりは点検アプリの `src/lib/extinguisher-ledger.ts` の `EXTINGUISHER_RULES` 1 か所。違っていれば、ここを直すだけで画面の印と集計が変わる。

| # | 確かめること | いまの作り（仮） |
|---|---|---|
| R1 | 「製造年から N 年を経過」の数え方 | **製造年 ＋ N 年の年から**対象（2016 年製は 2026 年から耐圧性能点検）。★2026-10-30 橋本さん「OK」＝このまま |
| R2 | 二酸化炭素・ハロゲン化物の内部・機能の点検 | 年数では出さない（「年数では求めない」と表示）。耐圧性能点検の除外は資料で確認済み |
| R3 | 化学泡の「設置後 1 年」 | 台帳に設置年が無いので**製造年**で数える（画面にもそう書く）。設置年の欄を足すかは返事しだい |
| R4 | 耐圧性能点検の「以後 3 年ごと」 | 前回の年 ＋ 3 年の年から。ただし製造年から 10 年より前には戻さない（腐食などで早めに行った分） |
| R5 | 交換の目安 | 製造年 ＋ 10 年の年まで。その年は「今年」、過ぎたら「過ぎています」（★「使えない」とは書かない） |
